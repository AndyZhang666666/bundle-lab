# 定向触达、预演直存与冻结条件核对

2026-11-11 · 开发分支 `feat/targeting-validation-loop-20261111`。本轮未合并或部署；公开站点仍以原发布版本为准。

本轮面向正在核对套餐账本的人：减少既有顾客让利、留存一个可比较的条件，再用同口径观察检查冻结计划。保留现有暖色工作纸、原生按钮与数值输入、矩阵紧接工作台的顺序，以及桌面并排的两项经济边界。没有改收益公式、模型版本或来源存储结构。

## 三条完成路径

1. **选择触达假设，再核账。** 公开菜单100%、人工发券50%、结账加购15%仅修改 `existingRedemption`，仍可手工输入任意0–100%的有效数值。选择状态由当前实际比例派生；手工改成50%会识别人工发券，37%显示自定义。采纳率、成本、折扣、商品、CSV构成与来源说明均保留。不同来源继续各自保存。
2. **预演后直接存入对比。** 格点仍先预演。直接存通过原 `createStrategy` / `addStrategy` 和原本机存储进入实际下一位置A、B或C；没有基准时先存A。冻结预演的精确折扣、三档采纳、模型与来源。取消不写任何记录；直接存不改工作输入、未提交名称／理由或旧快照。三个位置满后禁用直存，提示先导出比较卡、再移除一份。原“应用这组条件”行为继续保留。
3. **观察对照该计划的冻结条件。** 由冻结商品、人群与假设调用原模型得到保本采纳；不读取当前工作输入。已知补齐率低于边界时显示尚差的百分点和下一步条件；相等或高于边界显示达到模型条件。未知／零分母、全部已买齐、非正新增贡献或不可达边界显示暂不能判断。达到模型条件仍需核实成本、领折扣行为与基线，不是因果、显著性或上线结论。

## 状态与接口约定

- `applyTargetingPreset`仅替换一个参数，并保留完整来源草稿；选择名称不进入模型公式。
- `createSensitivityPreview`可附带冻结来源；旧四参数调用仍兼容。新直存同时检查完整输入签名与来源，旧预演不能被静默改写后保存。
- `StrategyBench`继续拥有唯一的方案状态、持久化和名称／理由草稿；通过渲染回调把直存动作交给排在它前面的矩阵，没有第二套快照存储。
- `observationBreakEvenCheck`只接收观察与冻结计划。`validationPlanReport`在JSON导出派生 `frozenBreakEven` 和逐组 `boundaryChecks`，Markdown输出同一判断；恢复仍由原计划解码器校验冻结输入与版本。存储键和模型版本未变。
- 满位、重复输入、过期预演和存储失败均有可见说明。存储失败时内存快照可继续导出，不冒充已经写入本机。
