# PRD：bundle-lab

一页纸。改动请同步更新 `DECISIONS.md`。

## 用户

没有算法团队的中小电商 / 餐饮运营。手上有订单明细导出（CSV），会看表格，不会写 SQL，
更不会跑关联规则。想回答的问题只有一个：**该不该做套餐，做哪个，推给谁。**

## 问题

客单价低，团队的第一反应通常是「用户不愿意多买」，于是加补贴、发券。
但很多时候真正的原因是**商品结构和点单结构错位**：多人订单占比不低，菜单却全是单人份，
用户凑不成一套就少点。这个判断需要拆订单结构才看得出来，而拆结构在多数团队里是人肉拉数 + 拍脑袋。

这个工具把「从订单里找组合机会 → 估算收益 → 出建议」做成一条可复用的链路，
让不会写 SQL 的人也能拿到有依据的结论，而不是一个「感觉可以试试」。

## 范围（四个页面）

| 页面 | 输入 | 输出 |
|---|---|---|
| 订单画像 | CSV 或内置合成数据 | 客单 / 商品数分布、多人 vs 单人对比、**错位信号一句话** |
| 组合发现 | 上一步的订单 | 支持度 / 置信度 / lift、命中订单数、命中客单 vs 全体，可分群、可调阈值 |
| 收益推演 | 选定组合 + 折扣 / 成本 / 采纳率 | 三档客单与毛利变化、盈亏平衡采纳率、3 组合横向比 |
| 建议输出 | 前三步结果 | 一页纸策略建议（推给谁 / 推什么 / 预期 / 风险），Markdown 导出，可选 LLM 润色 |

配套：校验页（把 `results/` 里的数字摆出来）、方法与假设页（公式和参数来源）。

## 不做什么

- **不接真实平台 API**。输入就是 CSV，这是分析工具不是系统。
- **不做在线推荐服务**。所有计算在浏览器端一次算完，没有服务端。
- **不做定价优化**。套餐价 = 原价 × 折扣，折扣是手动滑杆，工具不搜最优解。没有真实 A/B 数据，寻优出来的是假精度。
- **不做库存**。
- **不用任何真实业务数据**。全部合成，生成规则公开。

## 成功标准

**算法层**：
- 对预先植入了已知组合的合成数据，召回率 ≥ 4/5，且植入组合进前 10
- supp / conf / lift 与手算一致（10 条订单 fixture 全部断言通过）
- 能回答「多少订单量才够用」—— 有明确的可用线

**产品层**：
- 一个不懂关联规则的人，打开订单画像页 10 秒内能看懂那句「错位信号」
- 建议输出页的条目能直接复制进周报，不需要二次翻译
- 每个页面上的数字都能追溯到公式或 `results/`，没有凭空冒出来的

**工程层**：
- `npm run build` 无报错，静态导出可直接部署到 GitHub Pages
- 代码里没有任何 API key；LLM 只做 BYO-key
- README 前三节一个不懂本行的人能读懂
