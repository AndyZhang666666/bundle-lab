# 从调参数到比较取舍

2026-11-01，开发分支 `feat/product-depth-20261101`。本地实现与静态构建完成，待官网统一浏览器审阅；未发布。

## 本轮解决什么

原工作区能计算自己的套餐，但改完参数后没有固定的对照；三档柱形图也看不见折扣与采纳共同变化时，结论在哪些条件下翻转。新工作区把“保留输入—只改一个条件—对齐差异—记录选择”连成一次任务。

输入区优先商品、折扣与中档采纳。人群基线、成本、既有整套者领折扣率和低／高档按需展开。结果仍是新增毛利贡献减既有顾客让利，负数与不可达平衡点保持可见。没有新增收益模型、最优定价或经营效果声明。

## 方案快照

- `bundle-lab:strategies:v1` 与原内置 v2／自建 v1 草稿分开。最多三份输入，含商品、价格、人群、全组假设、来源、保存时间和模型版本。
- 第一份是比较基准 A；表中对齐商品、折扣、采纳、贡献、让利、增量毛利和平衡点，并列出相对 A 的改变。方案按100覆盖订单归一，不把多个方案收益相加。
- “复制后调整”把输入副本放入“我的算例”；原快照不变。完全相同的输入不重复保存，来源/key变更不会伪装成新策略。移除可撤回；下一次方案修改后撤回入口失效，避免覆盖后续工作。
- 人明确选择方案，可以填写理由。理由修改后需确认再导出；卡片包括所有输入、差异、结果、选择和来源。未选择时也可导出，明确写“尚未选择”。
- 恢复校验拒绝损坏、超限、缺失输入、重复ID与模型版本不同的记录，不自动改写旧记录。用户主动保存新方案时会替换此处旧记录；保存失败仍能操作和导出。

## 条件地图

- 折扣与中档采纳的二维表逐格调用既有 `simulateStats`。坐标为一组明确条件点，包含当前精确输入；其余人群与成本固定。
- 颜色区分正向、负向、持平，当前输入有描边；数字符号和按钮可访问名称不依赖颜色。格点可用键盘聚焦和激活，窄屏在地图自身滚动。
- 点击仅预演，展示相对当前的毛利变化和平衡条件；取消不改输入。确认只改折扣和中档采纳，必要时使用既有 `setAdoption` 联动低／高档以保持顺序。
- 地图不是价格弹性、收益概率或未来预测。已有方案快照不随预演或确认改变。
